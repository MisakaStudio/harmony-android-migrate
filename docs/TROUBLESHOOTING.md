# 常见问题

| 情况 | 处理方法 |
|---|---|
| 找不到备份元数据 | 选择包含 `.info.json`/`info.json` 与 `files` 的会话目录，不是 U 盘根目录；旧 `info.xml` 未支持 |
| 密码/认证失败 | 核对密码和备份完整性；保留原始文件，不尝试忽略认证标签 |
| `partial_conversion_blocked` | 阅读电脑端失败报告；有缺附件、未知状态或未支持记录。仅在接受缺失范围后使用 `--allow-partial` |
| `unknown_target_format` | 样本不是已支持格式；尝试原工具导出的未加密 XML。不能把任意厂商加密备份改扩展名后使用 |
| 目标样本没有卡 ID | 空样本只能证明格式；用 USB/安装器读取，或另提供有记录的脱敏结构作适配研究 |
| `choose_device` | 没有唯一已授权设备；指定 `--serial`，不自动选第一台 |
| `probe_needs_phone_action` | 解锁手机，在 USB 版允许读取 SIM 并刷新；普通版不提供此 USB 通道 |
| `active_phone_batch` | 先完成/核验原批次，恢复默认短信应用并结束批次，再传入或切换版本 |
| `apk_signature_mismatch` | 开发版或其他来源 APK 使用了不同签名；先导出私有备份，不能直接卸载丢掉续传日志 |
| 权限被 ROM 拒绝 | 查看系统授权与安装来源策略；USB 版不会绕过权限，可考虑 XML 路径 |
| 卡 1/卡 2 不显示 | 先核对短信订阅与通话账户，再抽查 ROM 界面。不要统一写死 `simid=sub_id`；私有字段须有目标记录证据 |
| 中途关闭/断电 | 保留同一输入、SIM 映射和应用数据，打开原批次预检查再继续；不清除日志 |
| `completed_record_changed` | 已写入记录发生后续变化，工具停止避免覆盖；导出报告人工核查 |
| 恢复默认应用后仍不能结束 | 检查待处理新消息/彩信通知/发送请求。导出报告只保存证据，不会自动将其标记已处理 |

提交问题时只提供机型、版本、错误码和匿名数量。完整 `report.json`、目标 profile、备份 ZIP 都可能含私有信息；不要直接上传到 Issue。
