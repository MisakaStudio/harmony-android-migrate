# 架构与适配边界

```text
鸿蒙本地备份
  → 元数据/清单检查
  → AES-GCM 认证解密（临时私有目录）
  → 兼容库 + 原始库交叉核对（保留 WAL）
  → 标准化记录 + 来源槽位 + 完整性报告
       ├─ SIM map → SMS Backup & Restore XML
       └─ native JSON → Android 安装器现场映射/预检查/备份/导入

目标信息来源：手工 map / ADB 候选 / Android 公共 API / 目标备份样本
```

## 电脑端

- `backup.py` 只接受明确支持的密钥封装和数据库路径。模块不存在与清单文件缺失区别处理。所有声明的分卷必须存在并通过认证。
- `records.py` 输出统一记录，多重集校验不把相同内容的两条源记录合成一条。来源 ID 保持稳定，重复实例具有不同 ID。
- `sim.py` 单独验证映射。仅短信或仅通话不强制填另一类的 ID。组件规范化不改变账户身份。
- `target.py` 识别目标格式家族，提取候选而非复制目标消息。读取不到的关系保留 unresolved。
- `adb.py` 固定已选择设备，拒绝多设备自动选第一台；不 root、不自动改默认卡或 AppOps、不保存原始敏感 dump。
- `formats.py` 与 `cli.py` 负责有完整性报告的产物。默认不发布部分数据；现有输出目录不被覆盖。

## Android 端

- `PackageData` 在取得写权限前验证 schema、字段白名单、记录 ID、附件哈希与上限。
- `DeviceProfile` 使用公开 API 获取订阅和电话账户关联；需要手工决策的关系不会被数字相同的假设替代。
- `MainActivity` 提供 SAF、USB 私有通道、映射确认、历史报告导出和角色恢复引导。批次开始后映射被冻结。
- `MigrationService` 用前台服务和进程/文件锁防止重复执行；备份和导出共享互斥。
- `MigrationEngine` 只追加新记录，不自动改目标已有记录的 SIM。跨卡相似记录需明确接受。
- 日志绑定输入和映射，逐记录记录准备、插入 URI、完成状态。MMS 父记录、地址、图片、SMIL 全部检查后才完成。
- 元数据头与按 source ID 分片的操作文件分别原子保存；不会每写一条就重写全部历史。读写状态文件在进程内串行化，批次写入与导出另有文件锁。
- 不完整 MMS 只有在日志、合成消息标识、创建者和目标行身份都匹配时才续传；不能证明所有权的记录不会被覆盖。
- 已完成记录后续被修改时停止，不把用户修改当作需要覆盖的残缺数据。

## 新增格式/厂商适配

1. 确认主来源或脱敏样本中的字段语义、时间单位、枚举和权限条件。
2. 新目标格式需有明确检测签名、解析器和可验证写入规则；不能仅复用相似字段名。
3. 新厂商通话字段需要目标样本或 API 证据，加入白名单并测试。不能写成全品牌默认值。
4. 添加合成测试，覆盖缺失、空类别、未知字段、真实重复、多 SIM 和中断状态。
5. 更新兼容矩阵，分别标注结构测试、模拟器和实体机证据。

## 数据与代码分离

仓库不保存实际备份、号码、ICCID、通信正文、密码、签名私钥或用户目录。测试数据由代码合成；开发机私有验证文件应放在仓库外或已忽略目录。源包与 APK 不内置数据。

Android 的系统文档提供方可能将用户手动导出的文件同步至所选云盘；工具本身没有联网代码或上传服务。
